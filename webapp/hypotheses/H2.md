Hypothesis 2: Simplicity bias
Statement of the hypothesis
Neural networks — including transformers — preferentially learn the simplest features that fit the training data, and this preference is the dominant determinant of how they generalize. When multiple features are jointly predictive of the label in training, gradient-based optimization on overparameterized networks does not learn a balanced combination; it concentrates almost entirely on whichever feature is simplest under the network's implicit complexity measure. Anything more complex is suppressed or ignored, even when the simpler feature alone is strictly worse on the i.i.d. test set than the more complex feature would be. OOD generalization, on this view, is determined by whether the simple feature the network has locked onto continues to be predictive in the OOD distribution. When it does, generalization looks excellent; when it does not, generalization fails sharply, and the model does not gracefully fall back to using the more complex but still-available feature, because that feature was never learned with usable strength in the first place.
The hypothesis treats simplicity bias as both the explanation for why over-parameterized networks generalize at all (a positive contribution: the simplest hypothesis is often correct, providing implicit regularization) and the explanation for why they generalize so brittly (a negative contribution: when the simplest hypothesis is wrong OOD, nothing else has been learned). The same mechanism produces both behaviors.
Definitions
Simplicity bias is the tendency of standard training procedures (typically SGD or Adam on overparameterized networks with cross-entropy or hinge loss) to converge to functions that are simple under some implicit complexity measure, when many functions in the hypothesis class fit the training data equally well. The relevant complexity measure is not fixed across the literature; different formalizations include:
Decision-boundary complexity: number of pieces, curvature, or VC-style measures of the function the network implements (Shah et al. 2020).
Parameter-function map bias: under random parameter initialization, the prior probability that the network implements a given function is sharply concentrated on simple functions, where simplicity is operationalized via Lempel–Ziv complexity, Boolean entropy, or Kolmogorov-style measures (Valle-Pérez, Camargo & Louis 2019).
Boolean sensitivity: for a function f: {0,1}^n → {0,1}, the average sensitivity is the expected number of input bits whose flipping changes the output. Low-sensitivity functions depend on few input variables in any local region; high-sensitivity functions like parity require attending to all bits jointly (Bhattamishra et al. 2023).
Frequency-domain simplicity ("spectral bias"): networks fit low-frequency components of the target function before high-frequency components; "simple" = low frequency.
Gradient starvation (Pezeshki et al. 2021) is the specific dynamical mechanism: when a small set of features explains most of the training loss, gradients for these features dominate, suppressing learning of any features whose learning signal is conditional on the dominant features being modeled correctly. Once a dominant feature has driven the loss low, gradients on competing features go to zero before those features have been learned — they are starved.
The parameter-function map is the (typically many-to-one) mapping from network parameters to the input–output function the network implements. A parameter-function map is biased toward simple functions if the volume of parameter space implementing simple functions is exponentially larger than the volume implementing complex functions, so that a random initialization is overwhelmingly likely to land near a simple-function basin.
Literature
The conceptual foundation is Valle-Pérez, Camargo & Louis (2019, ICLR), who argue that the success of deep learning despite massive overparameterization is explained by an exponential bias of the parameter-function map toward simple functions. They show empirically and via PAC-Bayes arguments that, under random initialization, the prior probability of a network implementing a function f decays approximately as 2^(−K(f)) where K is a complexity measure (Lempel–Ziv on Boolean truth tables, generalization error after training, etc.). On this view, SGD does not "search" for simple solutions — the parameter space is such that simple solutions occupy almost all of it. This reframes generalization as inheriting a Solomonoff-like prior from the architecture itself.
Shah et al. (2020) sharpen the simplicity-bias story into its problematic form. They construct synthetic datasets — "LMS" (Linear-Multi-Slab) and "MNIST-CIFAR" composites — where multiple features predict the label, with one designated as "simple" (linearly separable, low-dimensional) and others as "complex" (requiring nonlinear boundaries but still fully predictive). Their key empirical findings: (1) Even when every feature alone gives 100% test accuracy, the network uses only the simplest one; the others are not represented usefully in the learned function. (2) When the simple feature is strictly worse than the complex features (the simple feature is only 90% predictive while the complex features are 100% predictive), the network still uses only the simple feature, accepting the 10% error rather than learning a complex feature. (3) Simplicity bias persists across architectures (MLPs, CNNs, ResNets), optimizers (SGD, Adam), and most training conditions. (4) Three downstream pathologies follow: poor OOD performance under distribution shifts that break the simple feature, adversarial vulnerability (because the network is essentially a low-dimensional classifier and small perturbations along the simple feature flip predictions), and suboptimal generalization under specific i.i.d. shifts. They prove the bias formally for one-hidden-layer networks with hinge loss on their synthetic distribution. They also show that ensembling and adversarial training only partially mitigate the effect — extreme simplicity bias is not a small-data phenomenon and is not easily debiased by standard techniques.
For transformers specifically, Bhattamishra et al. (2023, ACL) operationalize simplicity via Boolean sensitivity and conduct an extensive study on Boolean functions. Their findings: (i) Random (untrained) transformers have prior mass concentrated on low-sensitivity functions — the architectural prior is itself biased toward simplicity. (ii) When trained on Boolean tasks, both transformers and LSTMs preferentially learn low-sensitivity functions, but transformers converge to functions of lower sensitivity than LSTMs. (iii) On sparse parities and other low-sensitivity functions, transformers generalize near-perfectly even with noisy labels, while LSTMs overfit. (iv) On high-sensitivity functions like full parity, transformers fail to generalize. This explains an apparent paradox in the formal-languages literature — transformers seem theoretically less expressive than LSTMs on languages like PARITY, yet outperform them in practice — by noting that the practical success comes from the natural-language tasks transformers do well on being predominantly low-sensitivity, matching the architecture's bias.
Vasudeva et al. (2024) extend this further, providing additional theoretical and empirical evidence that transformers are biased toward learning low-sensitivity functions across a wider range of settings, and proposing methods to mitigate this where the target task requires high-sensitivity computation. Hahn & Rofin (2024) corroborate the sensitivity framing theoretically.
Pezeshki et al. (2021, NeurIPS) provide the dynamical account in gradient starvation. In a controlled setting where two features each separately predict the label, they show analytically and empirically that whichever feature has the larger initial alignment with the gradient dominates training, and once that feature has driven the training loss to near zero, gradients on the second feature vanish — the second feature is starved. This explains why simplicity bias is not just a "preference" but an exclusion: alternative features are not weakly learned, they are not learned at all. Tiwari & Shenoy (2023) propose the "feature sieve" as a remediation: iteratively training auxiliary models to capture the dominant simple feature, then suppressing it in the main model's representations to force it to find alternatives. This recovers OOD performance on Waterbirds-style benchmarks but requires knowing what the simple shortcut is.
Hermann & Lampinen (2020) examine which features networks actually represent under standard training, finding that networks systematically (a) increase reliance on task-relevant features that are easily decodable from untrained networks, (b) suppress reliance on non-discriminative features, and (c) show invariance to features that are present but non-predictive. The picture is consistent: training does not produce a balanced representation of all useful features; it produces a sparse, simplicity-aligned representation.
Across the literature, two important caveats appear. First, the "simplicity" measure that explains a given empirical finding is often only informally specified, and different operationalizations (decision-boundary curvature, sensitivity, frequency, parameter-volume) do not always agree. Second, simplicity bias can be a feature rather than a bug — when the simple solution is the correct one, simplicity bias gives strong i.i.d. and OOD generalization; the failure mode is specifically when the simple solution is correct in training but wrong OOD. The hypothesis is therefore best stated not as "networks fail because they are biased toward simple solutions" but as "networks' OOD behavior is sharply determined by which feature the simplicity bias selects, and on whether that feature remains predictive OOD."
Prerequisites for testing
For experimental setups where the hypothesis predicts specific OOD generalization patterns, testing it requires a way to identify, before training, which features are "simpler" under the relevant complexity measure, so that the hypothesis's predictions can be made falsifiable. This is straightforward in synthetic Boolean-function settings (sensitivity is computable) and in vision settings with explicitly constructed simple/complex feature splits (Shah et al. 2020), but is harder in natural-language fine-tuning experiments where the candidate features are abstract.
For LLM-fine-tuning experiments, the prerequisite is either (a) a principled ranking of candidate features by some operational simplicity measure (e.g., n-gram statistics, surface-form predictability, length, lexical-overlap statistics — any of which approximates "simple" in the sensitivity / frequency sense), or (b) preliminary linear-probe / attribution analysis to determine which features the model is actually using post-finetuning. Without one of these, the hypothesis can post-hoc rationalize most generalization patterns by selecting an appropriate complexity measure after the fact, and its predictions are correspondingly weak. If the experimental paradigm has not yet been instrumented to identify candidate-simple features, a preliminary measurement pass — either statistical analysis of the fine-tuning data or probing the fine-tuned model — is prerequisite.
